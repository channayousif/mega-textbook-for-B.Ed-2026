FINDINGS
1. RTL and language: every page renders with <html dir="rtl" lang="ur"> at all
   three viewports; h1 matches each file's title frontmatter.
2. Nastaliq: the self-hosted Noto Nastaliq Urdu webfont is loaded
   (document.fonts.check true on all six pages, including a probe string
   covering the unit's mathematical vocabulary) and is the computed prose
   font; line-height 2.2 per src/css/custom.css. No horizontal overflow at
   1280, 360 or 794 px on any page (scrollWidth == clientWidth everywhere).
3. Embedded Latin in the Urdu pages is limited to expected runs: course code,
   breadcrumb course title (catalog is English-only), the TranslationStatusBadge
   ("Draft translation not yet human-reviewed") and PrintHandout ("Print /
   Save / PDF") shared UI components, Bloom tags (Remember/Understand/Apply/
   Analyze/Evaluate) and MCQ/RRQ/ERQ labels (course-wide convention, kept in
   Latin in every unit), citation names/URLs, and the textbook.com.pk SVG
   watermark. Numerals are Western digits throughout, matching the English.
4. Figures: all six .ur.svg variants are actually rendered on the UR pages
   (img src confirmed, element boxes ~703x424 at desktop). All six are
   horizontally mirrored per style guide v4.1 (panels reflected about the
   viewBox centre, text-anchor start/end swapped, watermark moved to the
   start side), in light and dark variants, with translated labels and
   Nastaliq-first font stacks.
5. Figure label fit under REAL Nastaliq metrics (figure-nastaliq-geometry.txt,
   v3 method - same-origin webfont + direction:ltr to reproduce standalone
   <img> anchor semantics; v1 used a fallback font because about:blank blocks
   the cross-origin @font-face, v2 accidentally measured in RTL base
   direction; both iterations are preserved as scripts):
   - fig-U4-1, fig-U4-2, fig-U4-3, fig-U4-4 (UR): every text element fits its
     panel and the viewBox. No problems.
   - fig-U4-6 (UR): two "فارمولا یا طریقہ" column labels overflow the viewBox
     left edge: "کتابیں ضرب جلد کی موٹائی، پھر شیلف لمبائی پر تقسیم"
     (bbox x=-22.7, w=236, h=30.4) and "لمبائی ضرب چوڑائی ضرب اونچائی، پھر
     1,000 سے" (bbox x=-16.4, w=224.4). pixel-clip-analysis.txt confirms glyph
     ink touching the cut left edge in the y-band 291-297 (the shelf row).
     The clipped edge removes the sentence-final operation words (تقسیم /
     سے 1,000) - i.e. the "divide by shelf length" and "then by 1,000" steps.
     Same strings and anchors in fig-U4-6.ur.dark.svg, so both theme variants
     are affected. Reported as a blocking finding.
   - English-side observations (no UR impact, G3/owner territory, advisory):
     fig-U4-5.svg "estimate with round numbers:" starts 18px left of its
     panel box; fig-U4-6.svg "length x width x height x 1,000" extends 26px
     past the table border (still inside the canvas).
6. Figure font reality on student devices: the Figure component embeds SVGs
   via <img>, which cannot use the page's Nastaliq webfont, and this host has
   no system Urdu font (fc-match falls back to DejaVu Sans). On-page prose is
   webfont-served and verified; figure labels render in the student OS Urdu
   font (Nastaliq on Android/Windows-with-Urdu-typesetting, Naskh on iOS/
   macOS). The clipping in finding 5 is measured with the real Nastaliq
   webfont and also reproduces with the fallback font (v1 measured the same
   two labels at x=-51.6 and x=-72.2), so it is not font-dependent.
