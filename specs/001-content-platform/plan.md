# Implementation Plan: Bilingual Content Platform

**Branch**: `001-content-platform` | **Date**: 2026-07-17 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-content-platform/spec.md`

## Summary

A public, bilingual (English + Urdu) digital textbook for the B.Ed (4-Year) programme, built as a **static Docusaurus v3 site** where content is Markdown/MDX + JSON category files and **adding a course is a content-only change**. The platform delivers: per-page EN↔UR toggle with RTL Nastaliq rendering; Semester → Course → Unit navigation autogenerated from folders; offline bilingual local search; the five per-unit sections (Content, Activities, Formative, Summative, Teacher Notes) plus a per-course overview; client-side A4 print handouts; and a build-time validation gate that blocks publish on missing traceability metadata or EN↔UR structural drift. No database and no backend in this feature (application state lands in later specs). Technical approach and all resolved unknowns are in [research.md](./research.md); the on-disk content model is in [data-model.md](./data-model.md); front-matter contracts are in [contracts/](./contracts/).

## Technical Context

**Language/Version**: TypeScript 5.x on Node.js 20+ (local Node 22.22.1); content in Markdown/MDX
**Primary Dependencies**: Docusaurus v3 (classic preset, TS); `@easyops-cn/docusaurus-search-local` (bilingual offline search); `gray-matter` + `ajv` + `ajv-formats` (front-matter validation); self-hosted Noto Nastaliq Urdu webfont; Playwright (RTL / narrow-viewport / A4 print-emulation checks)
**Storage**: Filesystem / Git — content is Markdown/MDX + `_category_.json` + `catalog/courses.json`. **No database** in this feature (Supabase is a later-spec concern, explicitly out of scope)
**Testing**: Vitest (or Node built-in test runner) for `validate-content` fixtures; Playwright for render/RTL/print; `docusaurus build` (both locales) as the CI integration gate; Lighthouse (CI) for perf/accessibility budgets
**Target Platform**: Static site — modern + low-end mobile browsers (Android on 2G/3G/Slow-4G); deployed to a free static host (Vercel; GitHub Pages fallback)
**Project Type**: Single static-content project (Docusaurus site at repo root; no frontend/backend split)
**Performance Goals**: EN↔UR toggle < 2s (SC-001); content text first paint < 2.5s on Slow-4G (SC-002); catalog reachable in ≤ 3 nav steps (SC-003); ≥ 95% of bilingual searches return a relevant result (SC-004)
**Constraints**: Content page text payload < 200 KB excluding images (SC-002, Constitution V.5); RTL-correct Urdu with Nastaliq webfont + fallback; no secrets/access-control in the static bundle (Constitution V.2); adding a course = zero platform-code changes (SC-006)
**Scale/Scope**: 8 semesters / 132 credit hours / ~40+ courses all scaffolded; authored content Sems 1–4 first; one frozen "golden" unit (EFMP-301 U1) sets the quality bar

### Source Code (repository root)

Docusaurus places content and platform code at the repo root; the "single project" layout below is the concrete target. **Content dirs grow per course with no platform-code change** (Constitution V.4).

```text
docusaurus.config.ts          # site + i18n (en default, ur rtl) config
sidebars.ts                   # autogenerated Semester → Course → Unit sidebar

docs/                         # EN content (source of truth for structure)
└── semester-{1..8}/
    └── <course-code>/
        ├── _category_.json           # course label + sidebar position (category.schema.json)
        ├── course-overview.mdx        # per-course overview (course-overview.schema.json)
        └── unit-NN/
            ├── index.mdx              # Content        ┐
            ├── activities.mdx         # Activities     │ five fixed files
            ├── formative.mdx          # Formative      │ (unit-frontmatter.schema.json)
            ├── summative.mdx          # Summative      │
            └── teacher-notes.mdx      # Teacher Notes  ┘

i18n/ur/                      # UR mirror (Docusaurus i18n); missing files fall back to EN
└── docusaurus-plugin-content-docs/current/semester-{1..8}/...

src/
├── components/               # MDX components: Glossary, BloomTag, ActivityCard,
│                             #   PrintHandout, ObjectiveList, TranslationStatusBadge
├── css/custom.css            # [dir='rtl'] rules, @font-face Nastaliq, @media print (A4)
└── theme/                    # minimal swizzles only if required

static/fonts/                 # self-hosted Noto Nastaliq Urdu (WOFF2, subset)

catalog/courses.json          # machine-readable 8-semester catalog (seed for scaffold)
glossary.json                 # bilingual glossary terms ({term, definition_en, definition_ur})

scripts/
├── validate-content.mjs      # gray-matter + ajv gate + structural + EN↔UR parity + glossary ref + weighting-sum checks
└── scaffold-catalog.mjs      # generate folders/_category_/overview/placeholder units

tests/
├── unit/                     # validate-content fixtures (Vitest)
└── e2e/                      # Playwright: RTL, narrow-viewport, badges, A4 print

.github/workflows/ci.yml      # validate:content → build (both locales) → deploy + Lighthouse
```

**Structure Decision**: Single static-content project rooted at the repo (Docusaurus convention). No `frontend/`+`backend/` split because there is **no backend** in this feature (Constitution V.1; app state deferred to later specs). The only executable code is two Node build scripts (`validate-content.mjs`, `scaffold-catalog.mjs`) and a handful of typed MDX components — everything else is content the validator/generator operate over, preserving "one course = one content module."
