## C1: Leftover merge-fix worktrees held branches, causing 48 launch failures and 5-fix batch limit lockouts
- **Kind:** crew brief or planner fix
- **Cause:** When a merge-fix job failed or timed out, its worktree folder under `WT_DIR` remained attached to the branch because `cleanup()` skipped jobs with parents and failure paths did not force-remove the worktree. Git refuses `git worktree add -B <branch>` when another worktree folder has `<branch>` checked out (`fatal: '<branch>' is already used by worktree at '...'`). This produced 48 launch failures across 24 hours, stalling conflict repairs and causing 4 units (`gnas-301-u05`, `gnas-301-u06`, `gqur-300-u03`, `gqur-300-u05`) to hit the 5 merge-fix limit. Resolved on main in PR #358 (commit `b8764bc3`) by adding `freeBranch()` in `scripts/crew/crew.mjs:prepareWorktree`.
- **Recurrence:** 48 launch failures and 5 batch-limit failures across 24 h; 0 in slot 2026-10-29-00 following PR #358 merge.
- **Evidence:** PR #358; commit `b8764bc3`; commit `257d1d2a`; job:gnas-301-u05-review_en-conflict2; job:gnas-301-u05-review_en-conflict3; job:gnas-301-u06-review_en-conflict2; job:gnas-301-u05-review_en; job:gnas-301-u06-review_en; job:gqur-300-u05-review_en.
- **Proposed home:** Crew fix in `scripts/crew/crew.mjs` (`prepareWorktree`, `freeBranch`) and test in `tests/crew/worktrees.test.mjs` (merged in PR #358).
- **Signature:** `launch failed: <path> <path>: fatal: '<path>' is already used by worktree at '<path>'`
- **Registry:** new (resolved on main via PR #358).

## C2: Claude CLI 5-hour limit evades QUOTA_RE due to hyphen, burning job attempts as exit-1 failures
- **Kind:** crew brief or planner fix
- **Cause:** In `scripts/crew/workers.mjs:72`, `QUOTA_RE` includes `hit your (\w+ )?limit`. Because regex `\w` excludes hyphens, `hit your (\w+ )?limit` does not match Claude CLI's quota error `You've hit your 5-hour limit · resets ...`. Consequently, `crew.mjs:reapOne` failed to recognize the quota error (`quota` evaluated false), treating it as an unhandled worker crash (`worker exited 1:`). This burned job attempts (e.g. `gpks-402-u02-review_en`, `gpks-402-u05-review_en`, `gpks-402-u05-translate`, `gpks-402-u04-translate`) instead of cooling the worker and requeuing the job without using an attempt.
- **Recurrence:** 10 worker exit failures in 24 h.
- **Evidence:** log:gpks-402-u02-review_en.1.log:2; log:gpks-402-u04-translate.1.log:2; log:gpks-402-u05-review_en.1.log:2; log:gpks-402-u05-translate.1.log:2; `scripts/crew/workers.mjs:72`.
- **Proposed home:** Regex fix in `scripts/crew/workers.mjs` (`QUOTA_RE`): update `hit your (\w+ )?limit` to `hit your ([\w-]+ )?limit` (or `hit your [^.\n]+limit`).
- **Signature:** `worker exited n:`
- **Registry:** candidate I-0013 (raises recurrence and extends cooldown detection).

## C3: Concurrent unit jobs in course focus collide on tasks.md table rows, causing mass batch exclusions
- **Kind:** crew brief or planner fix
- **Cause:** When multiple units of the same course run concurrently under course focus (e.g. GPKS-402 units 1, 2, 3, 4, 5, 6), each unit branch commits updates to its own row in `specs/content/<course>/tasks.md`. When a batch merges to main, git merge flags conflicts on adjacent table rows for remaining branches. `scripts/crew/crew.mjs:resolveSharedConflicts` automatically reconciles conflicts in `glossary.json` and `static/content-status.json`, but leaves out `tasks.md`. As a result, 40 batch merge exclusions and 5-stage conflict loops occurred (e.g. `gpks-402-u03-author` underwent 5 consecutive merge fixes before hitting the batch exclusion limit).
- **Recurrence:** 32 single-path conflicts, 8 multi-path conflicts, and 1 batch-limit failure (`gpks-402-u03-author`) in 24 h.
- **Evidence:** job:gnas-301-u04-review_en; job:gnas-301-u05-review_en; job:gnas-301-u06-review_en; job:efmp-301-u05-review_en; job:gpks-402-u03-author; `scripts/crew/crew.mjs:835-853`.
- **Proposed home:** Dispatcher helper `mergeTasksMd` in `scripts/crew/crew.mjs` (`resolveSharedConflicts`): parse markdown table rows in `specs/content/<course>/tasks.md` by Unit ID and auto-merge non-conflicting unit row changes in the batch worktree, eliminating manual merge-fix jobs for independent unit rows.
- **Signature:** `left out of the batch: <path> conflicts with main (<path>).; merge fix queued`
- **Registry:** new.
