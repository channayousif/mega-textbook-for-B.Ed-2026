## C1: Course tracker merge failures hit 5-fix ceiling and permanently red-gate ready authoring jobs
- **Kind:** crew fix
- **Cause:** When multiple unit authoring jobs complete for the same course (such as EFPG-401 Units 2, 3, 4, 5, 6, 7), ready branches conflict with `main` on `specs/content/<course>/tasks.md`. Git's three-way merge cannot resolve these because `mergeTrackerRows` in `scripts/crew/batch.mjs` only keys table rows when both `Unit` and `Stage` columns exist; the top `## Units` summary table and single-line `## Status:` header are treated as plain lines. When concurrent branches update their own unit's status in the summary table or edit the status header, `mergeTrackerRows` returns `null`, excluding ready branches from hourly batches. Dispatcher-spawned conflict fix jobs manually resolve the merge, but by the next batch another branch has landed, re-conflicting `tasks.md`. After 5 consecutive merge fixes, jobs hit the hard ceiling and fail permanently with `gate_red` ("could not join a batch after 5 merge fixes"), losing authoring progress.
- **Recurrence:** 2 jobs permanently failed with 5-fix ceilings (`efpg-401-u03-author`, `efpg-401-u05-author`) and 4 batch exclusion failures in 24 hours (150 total exclusions since 2026-10-28; 15 five-fix ceiling failures historically).
- **Evidence:** `job:efpg-401-u03-author`; `job:efpg-401-u05-author`; `job:gqur-300-u05-review_en`; `job:efpg-401-u04-author`; `scripts/crew/batch.mjs:124-131`; `scripts/crew/crew.mjs:850-868`.
- **Proposed home:** `scripts/crew/batch.mjs` (`trackerLines` / `mergeTrackerRows`): extend table row keying to `## Units` tables keyed by `Unit` column alone when `Stage` is absent, and drop or auto-synthesize the single-line prose `## Status:` header, preventing false plain-line conflict rejections in `resolveSharedConflicts`.
- **Signature:** `could not join a batch after n merge fixes`
- **Registry:** matches proposed I-0021 (raises recurrence to 150 exclusions and 15 five-fix ceiling failures).

- **Signature:** `tasks.md status line still reads main's "units n, n and n authored; unit n english draft complete"; left unchanged under the never-change-main's-entry rule.`

## C5: Course tracker merges pull in out-of-scope sibling unit files, risking accidental cross-unit scope creep
- **Kind:** brief / skill
- **Cause:** When resolving `tasks.md` conflicts via `git merge origin/main`, git merges all changes on `main` since the authoring branch diverged. For fast-moving courses like EFPG-401, merging `main` pulls in newly authored sibling units (e.g. Unit 2, Unit 6, Unit 7 docs, figures, and Urdu mirrors) into a branch scoped only for Unit 4 or Unit 5. While necessary for clean git merges, workers frequently struggle with scope boundaries or risk accidentally touching or modifying sibling unit rows in `tasks.md`.
- **Recurrence:** 4 handoff notes in the window (`efpg-401-u04-author-conflict4`, `efpg-401-u05-author-conflict4`, `efpg-401-u05-author-conflict5`).
- **Evidence:** `job:efpg-401-u04-author-conflict4`; `job:efpg-401-u05-author-conflict4`; `job:efpg-401-u05-author-conflict5`.
- **Proposed home:** `scripts/crew/crew.mjs` (`mergeFixBrief`) and `.claude/skills/revise-topic/SKILL.md`: add explicit guidance for merge fixes stating that files brought in by merging `origin/main` outside the job's scope must remain untouched, and their existing tracker rows must be preserved as-is.
- **Signature:** `the merge brought main's <course> unit n and unit n authoring files into this branch; they are outside this job's scope.`
- **Registry:** new.
