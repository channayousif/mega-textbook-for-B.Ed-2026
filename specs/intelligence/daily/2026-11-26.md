## C1: `trackerLines` absorbs entire `tasks.md` into status block when file lacks subsequent `## ` headings
- **Kind:** crew fix
- **Cause:** In `scripts/crew/batch.mjs` (`trackerLines`, line 92), the status block loop `while (i + 1 < lines.length && !/^##\s/.test(lines[i + 1])) block.push(lines[++i]);` consumes every line until the next `## ` heading. When a course tracker lacks subsequent `## ` headings (such as `specs/content/efmp-409/tasks.md`), the status block absorbs the entire file including table rows. When `mergeTrackerRows` resolves conflicting status blocks by taking `ours` (`line = ol`, line 198), it silently drops all newly added unit rows from `theirs`. In the batch, `check-pipeline-gate.mjs` detects the unit's newly added `index.mdx` without a corresponding `G2 en-draft` row in `tasks.md` and fails `check:content`, excluding candidate branches.
- **Recurrence:** 8 batch exclusions in 24 h across EFMP-409 Units 3, 4, 5 (36 total).
- **Evidence:** `job:efmp-409-u03-author`, `job:efmp-409-u04-author`, `job:efmp-409-u05-author`; `history/prompts/efmp-409/crew-efmp-409-u05-author-conflict1.misc.prompt.md:73-75`; `history/prompts/efmp-409/crew-efmp-409-u05-author-conflict2.misc.prompt.md:73-75`; `scripts/crew/batch.mjs:92,198`.
- **Proposed home:** `scripts/crew/batch.mjs` (`trackerLines`): terminate status block consumption on table rows (`isRow(lines[i + 1])`) or blank lines preceding table headers, preventing table rows from being absorbed into status blocks.
- **Signature:** `left out of the batch: merged onto main's latest state, <path> fails npm run check:content (it could not join the hourly batch):; merge fix queued`
- **Registry:** new.

## C2: G3 review render inspection against production forces escalate on unmerged candidate assets
- **Kind:** brief / skill / tool fix
- **Cause:** Reviewers run `scripts/render-inspect.mjs --base https://textbook.com.pk`. Because candidate branches contain newly drafted unit pages or illustrations not yet deployed to production, `render-inspect.mjs` detects SHA mismatches between production and candidate HEAD, or receives HTTP 404 for candidate assets. Reviewers record finding F1 with severity `uncertain` ("Render and print inspection could not be performed"). Under ADR-0019 review logic, an unresolved uncertain finding automatically turns the review verdict into `escalate`, preventing newly authored units from passing G3 review.
- **Recurrence:** 5 review reports, 2 escalate handoffs in 24 h (EFMP-408 Unit 2, EFMP-304 Units 5 and 6, EFMP-303 Unit 6); 9 total.
- **Evidence:** `review:specs/content/efmp-408/reviews/unit-02/G3/agy-run1-20261125.json`; `review:specs/content/efmp-304/reviews/unit-06/G3/agy-cycle2-20261125.json`; `review:specs/content/efmp-304/reviews/unit-05/G3/agy-cycle2-20261125.json`; `review:specs/content/efmp-303/reviews/unit-06/G3/agy-cycle2-20261125.json`; `job:efmp-304-u05-review_en`; `job:efmp-304-u06-review_en`.
- **Proposed home:** `scripts/render-inspect.mjs` / `.claude/skills/review-unit/SKILL.md`: classify live-site SHA divergence or candidate asset unavailability as an advisory limitation rather than an uncertain finding when the unit is not yet merged, or provide an offline static check that does not require production deployment.
- **Signature:** `render and print inspection (npx viewport, table scrolling, desktop layout, an print, figure clipping) could not be performed`
- **Registry:** repeats 2026-11-25 C2 (raises recurrence to 9).

## C3: Concurrent jobs within a course collide on shared tasks.md and source excerpts
- **Kind:** planner fix / crew fix
- **Cause:** When multiple units of the same course are authored concurrently (e.g. EFMP-408 Units 2, 4, 5 and EFMP-301 Units 3, 5), branches concurrently append reading-estimate prose to `tasks.md` and citations to shared course source files (`specs/content/<course>/sources/texts/*.md`, such as `seifert-sutton-2009.md`). Because `mergeTrackerRows` in `batch.mjs` returns `null` when prose lines change non-identically, and git cannot auto-merge disjoint changes to shared markdown files without conflict markers, jobs are repeatedly excluded from batches and queued for sequential conflict-fix loops.

- **Proposed home:** `scripts/crew/planner.mjs`: serialize authoring jobs within the same course, or extend `resolveSharedConflicts` in `scripts/crew/crew.mjs` to auto-merge append-only sections in `sources/texts/*.md` and reading-estimate paragraphs in `tasks.md`.
- **Signature:** `left out of the batch: <path> conflicts with main (<path>).; merge fix queued`
