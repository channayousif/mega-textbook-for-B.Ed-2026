## C1: Re-tracking static/content-status.json on main causes check:content-status gate failures and leaves dirty uncommitted working trees
- **Kind:** crew brief or planner fix
- **Cause:** Although maintenance task M1 (`b1b4ee90`) untracked `static/content-status.json` on main, commit `d70aa57a` (`chore(efmp-304-u06): rebuild stale content-status.json`) re-added it into git tracking on main, followed by `ff5f99a6`. Because the file is tracked in git, any unit metadata edit (e.g. `tasks.md`) invalidates the committed report, causing `1 of 13 content gates failed: check:content-status` (40 log errors). Regenerating the file via `npm run build:content-status` produces a modified tracked file (`M static/content-status.json`), which workers are strictly forbidden from committing because repository rules prohibit modifying `content-status.json` or committing outside unit scope. Workers in 8 distinct handoffs (16 occurrences) were forced to leave the dirty report unstaged and uncommitted.
- **Recurrence:** 43 stale log errors, 40 check:content-status gate failures, 3 missing errors, and 16 handoff notes across 8 clusters in 24 h.
- **Evidence:** commit `d70aa57a`; commit `ff5f99a6`; log:efmp-301-u03-fix.1.log:4143-4152; log:efmp-302-u02-repair_en-conflict1.1.log; job:efmp-301-u03-fix; job:efmp-302-u04-fix; job:efmp-301-u05-fix; job:gict-300-u02-fix; job:efmp-303-u05-fix; job:efmp-301-u11-fix.
- **Proposed home:** Crew fix in `scripts/crew/crew.mjs` (untrack `static/content-status.json` from git and enforce untracked state in `check-docs-sync` or a pre-commit check so it cannot be re-tracked).
- **Signature:** `✗ <path> is stale - it no longer describes the working tree.`
- **Registry:** candidate I-0007 / I-0009 / I-0011 (raises recurrence; records regression of M1 untracked state).

## C2: Translation temporary reviewed flip unconditionally trips publication tracker assertions in check:pipeline-gate
- **Kind:** gate or check
- **Cause:** `.claude/skills/translate-unit/SKILL.md` Step 5 instructs translators to temporarily flip `translation_status` from `draft` to `reviewed` and run `npm run check:content` to verify parity, figures, and terminology key_terms. However, `npm run check:content` executes `check:pipeline-gate`. In `scripts/check-pipeline-gate.mjs:211-216`, if `translation_status === 'reviewed'`, the gate asserts that both `G4 ur-translation` and `G5 ur-review` rows are marked done in `tasks.md`. Because translation is currently in draft progress, neither row is done, causing `check:pipeline-gate` to unconditionally fail (`'G4 ur-translation' row for Unit N is not done (status: '▣')`, `'G5 ur-review' row for Unit N is not done (status: '▣')`). Workers get confused by the gate failure, attempt to resolve tracker rows, or fail the run if they do not flip back.
- **Recurrence:** 16 pipeline gate log errors, 15 check:pipeline-gate content gate failures, and 4 job failures in 24 h.
- **Evidence:** log:efmp-302-u03-translate.1.log:6203-6206; log:efmp-302-u04-translate-r1.1.log; log:efmp-303-u01-translate-r1.1.log; job:efmp-304-u01-translate; `scripts/check-pipeline-gate.mjs:211-216`; `.claude/skills/translate-unit/SKILL.md:169-173`.
- **Proposed home:** Gate check in `scripts/check-pipeline-gate.mjs`: decouple publication tracker assertions (G4/G5 done in tasks.md) from content quality checks (key_terms in terminology bank), or permit a `--skip-tracker` / `--draft-flip` option for temporary validation.
- **Signature:** `✗ pipeline gate failed with n finding(s):`
- **Registry:** new.

## C3: Review-evidence bound inputs include translation handoffs, invalidating sealed G2 manifest upon translation updates
- **Kind:** gate or check
- **Cause:** `scripts/lib/review-evidence.mjs:205-209` defines bound inputs for a unit by taking `specs/content/${code}`, filtering out `/reviews/`, `/intake/`, `tasks.md`, and `/.staging/`. It still does not exclude `specs/content/${code}/translations/`. Consequently, translation lifecycle files (`specs/content/${course}/translations/unit-NN/handoff.md`, retry logs) are bound into the English G2 gate manifest. When translators update translation handoffs or retry notes, the sealed G2 manifest hash is invalidated (`G2 en-draft: stale or incomplete input manifest`), blocking subsequent checks and causing pipeline gate failures.
- **Recurrence:** 1 handoff in 24 h (`job:intel-2026-10-27-distill`) and 4 failure jobs with pipeline gate findings (`job:efmp-304-u01-translate`, `job:efmp-304-u02-translate`, `job:efmp-304-u04-translate`).
- **Evidence:** log:efmp-304-u01-translate-r1.2.log:56-58; job:intel-2026-10-27-distill; `scripts/lib/review-evidence.mjs:205-209`.
- **Proposed home:** Gate exclusion in `scripts/lib/review-evidence.mjs` (`bound`): add `&& !p.includes('/translations/')` to the exclusion filter alongside `/reviews/` and `/intake/`.
- **Signature:** `<path> binds translation handoffs to gn manifest; adding <path>/ to exclusions would prevent post-translation gn invalidation.`
- **Registry:** repeats 2026-10-27 C1 (raises recurrence).

## C4: Planner schedules redundant translation retries when Urdu mirror is already complete on main
- **Kind:** crew brief or planner fix
- **Cause:** In `scripts/crew/crew.mjs:135`, `unitFacts()` checks `mirrorComplete: d ? mirrorComplete(listDir(d.unitDir), listDir(d.urUnitDir)) : false` on the local filesystem of the control checkout. If the control checkout has not pulled `origin/main` or if sparse checkout excludes `i18n/ur/...`, `listDir(d.urUnitDir)` returns empty. Consequently, `stagesFor` yields `translate` and queues a translation retry (such as `efmp-304-u04-translate-r1` and `efmp-303-u02-translate`) even though the complete Urdu mirror was already merged on `origin/main`. Workers launch in a fresh worktree, discover that all Urdu files, figures, and tests are already committed on main with nothing to change, and exit clean without committing. Detector I-0002 then fails the job with `the worker exited without committing any change`.
- **Recurrence:** 5 failures in 24 h (`the worker exited without committing any change`).
- **Evidence:** log:efmp-304-u04-translate-r1.1.log; log:efmp-303-u02-translate.1.log; log:gict-300-u01-translate-r1.1.log; job:efmp-304-u04-translate-r1; job:efmp-303-u02-translate; `scripts/crew/crew.mjs:135`.
- **Proposed home:** Planner fix in `scripts/crew/crew.mjs`: verify `git pull --ff-only` in the control checkout before planning, and inspect git index/tree (`git ls-tree`) rather than local filesystem reads that can be misled by sparse checkouts.
- **Signature:** `the worker exited without committing any change`
- **Registry:** repeats I-0002 / I-0004 (planner-side mirror detection).
