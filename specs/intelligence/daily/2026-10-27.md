## C1: Review-evidence bound inputs include translation handoffs, invalidating sealed G2 manifest upon metadata edits
- **Kind:** gate or check
- **Cause:** `scripts/lib/review-evidence.mjs` defines bound inputs for a unit by taking `specs/content/${code}`, filtering out `/reviews/`, `/intake/`, `tasks.md`, and `/.staging/`. It fails to exclude `specs/content/${code}/translations/`. Consequently, translation lifecycle files (`specs/content/${course}/translations/unit-NN/handoff.md`, retry logs) are bound into the English G2 gate manifest. When translators update handoff notes or retry logs following a translation run (as observed in GQUR-301 Unit 7), the sealed G2 manifest hash is invalidated (`G2 en-draft: stale or incomplete input manifest`), blocking subsequent checks and requiring manual re-execution of `prepare-gate-evidence`.
- **Recurrence:** 1 failure mode in 24 h (GQUR-301 Unit 7 translation validation).
- **Evidence:** phr:history/prompts/general/20261026-validate-unit-seven-urdu-retry.general.prompt.md; `scripts/lib/review-evidence.mjs:205-209`.
- **Proposed home:** Gate exclusion in `scripts/lib/review-evidence.mjs` (`bound`): add `!p.includes('/translations/')` to the exclusion filter alongside `/reviews/` and `/intake/`.
- **Signature:** `failure modes observed: earlier committed branch retained a stale gn manifest despite a stored passing log. post-commit validation also caught that updating tra`
- **Registry:** new.
