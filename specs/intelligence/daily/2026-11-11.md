## C1: Workers attempt to inspect /proc/pressure/* and worktree git internals, triggering external_directory auto-rejections that abort runs without commits
- **Kind:** brief / skill
- **Cause:** Workers in headless CLIs (particularly opencode) attempt to verify host resource metrics (`/proc/pressure/memory`, `/proc/pressure/io`) or inspect git internals (`.git` in a worktree points to `/home/a2ahs/mega_book_for_B.Ed/.git/worktrees/<name>`). Because these paths are outside the checkout root, opencode auto-rejects `external_directory` access. When a tool call is rejected, opencode halts and exits immediately without committing, producing 19 zero-commit exits and 14 permission-rejected errors in 24 hours.
- **Recurrence:** 19 empty worker exits and 14 rejected tool permission errors in the window (57 total empty exits since 2026-10-19; 60 permission rejections total).
- **Evidence:** `log:efpg-401-u07-author-conflict1.1.log`; `log:gicp-400-u07-translate-r1.1.log`; `log:gicp-400-u07-translate-r1.2.log`; `job:gicp-400-u07-translate-r1`; `job:giss-401-u05-translate-r1`.
- **Proposed home:** `scripts/crew/crew.mjs` (`briefRules`) and `AGENTS.md` ("Host resource limits"): clarify that `scripts/heavy.sh` handles PSI and host memory admission automatically, and strictly forbid reading `/proc/pressure/*` or accessing git internals outside the workspace checkout root.
- **Signature:** `error: the user rejected permission to use this specific tool call.`
- **Registry:** matches adopted I-0008 (evidence that out-of-worktree inspection boundaries need explicit brief rules).

## C3: Unhandled Gemini 503 capacity errors cause hard worker exit failures instead of triggering worker cooldown
- **Kind:** crew fix
- **Cause:** When Google Gemini API servers experience transient high traffic, `agy` exits with status 1 and logs `error: Our servers are experiencing high traffic right now... (UNAVAILABLE (code 503): No capacity available for model gemini-3.8-flash-high on the server)`. In `scripts/crew/workers.mjs`, `QUOTA_RE` only matches `\b429\b`, `rate limit`, `quota`, `at capacity`, etc., failing to match HTTP 503, `UNAVAILABLE`, `No capacity available`, or `high traffic`. The dispatcher records a hard worker failure instead of cooling the worker and falling back to the next runner.
- **Recurrence:** 2 worker exit failures and 4 log errors in the window (47 total worker exit failures).

- **Proposed home:** `scripts/crew/workers.mjs` (`QUOTA_RE`): add `\b503\b|unavailable.*capacity|no capacity available|high traffic` to `QUOTA_RE` so transient server capacity drops invoke `cool()` rather than burning job attempts.
- **Signature:** `error: our servers are experiencing high traffic right now, please try again in a minute. (unavailable (code n): no capacity available for model gemini-n.n-flas`
- **Registry:** new.
