## C1: Tracked and stale content-status.json on origin/main breaks fresh worktree gates
- **Kind:** brief / planner fix
- **Cause:** `static/content-status.json` is listed in `.gitignore`, but was committed and tracked on `origin/main`. Worse, the copy tracked on `origin/main` is stale (`report-content-status.mjs --check` fails immediately on a clean checkout of `origin/main`). Every fresh worktree checked out from `origin/main` inherits this stale generated file, causing `check:content-status` to fail before workers make any changes or run other gates. This is the single largest cause of gate noise across all stages.
- **Recurrence:** 25 stale errors + 23 content-status gate failures + 1 missing error + 2 multi-gate bundles = 51 signals in 24 h (over 340 total across all content-status variants).
- **Evidence:** log:efmp-302-u02-repair_en-conflict1.1.log; log:efmp-302-u02-repair_en-conflict4.1.log; log:efmp-302-u02-translate.1.log; log:efmp-301-u01-review_ur.2.log; job:gqur-301-u14-review_en (handoff: `static/content-status.json is tracked and out of date on origin/main; check:content-status fails there too`).
- **Proposed home:** Repository maintenance and dispatcher: untrack the file from git (`git rm --cached static/content-status.json`) so it is truly ignored, and ensure `prepareWorktree` in `scripts/crew/crew.mjs` runs `npm run build:content-status` when provisioning any worktree.
- **Signature:** `✗ <path> is stale - it no longer describes the working tree.`
- **Registry:** candidate I-0007 (raises recurrence; refines root cause from missing in fresh worktrees to tracked and stale on origin/main).

## C2: Translation skill's temporary reviewed flip trips pipeline gate on tracker status
- **Kind:** skill
- **Cause:** `.claude/skills/translate-unit/SKILL.md` (Step 5) instructs translators to temporarily flip `translation_status` from `draft` to `reviewed` and run `npm run check:content` to verify heading, term, and figure parity. However, `npm run check:content` runs `check:pipeline-gate`, which requires that any unit marked `reviewed` must already have completed `G4 ur-translation` and `G5 ur-review` rows (`✅` with reviewer initials) in `tasks.md`. Because an in-progress translation job has not yet completed G4 or G5, running `npm run check:content` during the flip inevitably fails `check:pipeline-gate` with `'G4 ur-translation' row for Unit N is not done`.
- **Recurrence:** 6 log errors + 5 content gate failures (46 total log errors, 16 gate failures) in this window.
- **Evidence:** log:efmp-302-u03-translate.1.log; log:efmp-302-u04-translate-r1.1.log; log:efmp-303-u01-translate-r1.1.log; `.claude/skills/translate-unit/SKILL.md:168-170`; `scripts/check-pipeline-gate.mjs:211-216`.
- **Proposed home:** Skill procedure in `.claude/skills/translate-unit/SKILL.md`: replace the instruction to run full `npm run check:content` during the temporary reviewed flip with targeted parity checks (`node scripts/validate-content.mjs`, `npm run check:figures`), or add a `--parity-only` flag to `scripts/check-pipeline-gate.mjs` to bypass tracker stage validation during pre-review parity verification.
- **Signature:** `n of n content gates failed: check:pipeline-gate.`
- **Registry:** new (distinct root cause from unsealed G2 English manifests).

## C5: Headless runner auto-rejects tool operations accessing /tmp/ outside worktree

- **Recurrence:** 5 permission-rejection log errors (30 total) and 1 failed read log error in 24 h.
- **Evidence:** log:efmp-301-u01-review_ur.1.log:238; log:efmp-302-u02-repair_en-conflict2.1.log:412; log:efmp-302-u02-repair_en-conflict2.2.log:189; log:efmp-303-u04-review_en.1.log.

- **Signature:** `error: the user rejected permission to use this specific tool call.`
- **Registry:** matches candidate I-0008 (raises recurrence; ready for weekly maintenance promotion).
