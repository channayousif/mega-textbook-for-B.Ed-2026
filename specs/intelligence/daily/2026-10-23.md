## C1: content-status.json still missing or stale in fresh worktrees
- **Kind:** brief / skill
- **Cause:** `static/content-status.json` is a git-ignored, generated artifact absent in fresh worktrees and invalidated after any edit. Workers run `npm run check:content` before building it, so `check:content-status` fails first and every subsequent gate summary inherits the failure. The cluster has grown: 18 missing + 14 stale + 23 content-status-only gate failures + 2 multi-gate bundles that include it = 57 harvested signals in this window. This is the single largest cause of gate noise.
- **Recurrence:** 57 signals here; 4th daily recurrence (2026-10-20 C1, 2026-10-21 C2, 2026-20-22 C1).
- **Evidence:** log:efmp-301-u01-review_ur.2.log:541; log:efmp-302-u06-translate-r1.1.log:11781; log:efmp-302-u02-repair_en_conflict4.1.log:639; job:gqur-301-u04-translate (handoff names `missing generated static/content-status.json`).
- **Proposed home:** crew brief gate-preparation step: run `npm run build:content-status` immediately before `npm run check:content`, including after merges and after any edit. Alternatively, run it automatically in `prepareWorktree` (`scripts/crew/crew.mjs`). Explain that Git cannot restore this generated artifact.
- **Signature:** `✗ <path> is missing. run: npm run build:content-status`
- **Registry:** matches candidate I-0007 (raises recurrence, ready for weekly promotion). This worker preparation gap is distinct from adopted I-0005's batch preparation.

## C4: Translator/repair edits fail on exact-match oldString
- **Kind:** skill
- **Cause:** Workers attempt `edit` tool calls where the `oldString` does not match the file exactly (whitespace, indentation, line endings). The tool rejects the call, wasting turns and producing `✗ edit <path> failed` diagnostics clustered alongside the `Could not find oldString` message. Both signatures trace to the same root cause: workers reconstruct file content from memory instead of reading it immediately before the edit.
- **Recurrence:** 2 edit-failed log errors + 2 `Could not find oldString` log errors = 4 signals in this window (4 recent, 4 total, new since 2026-10-18).
- **Evidence:** log:efmp-305-u03-translate.1.log:340-978 (multiple `Could not find oldString` and `No changes to apply: oldString and newString are identical`); log:gict-300-u05-translate-r1.1.log; log:gqur-301-u05-translate.3.log.
- **Proposed home:** rule or skill procedure: read the target file (or the relevant passage) immediately before constructing an `edit` call, and verify whitespace/indentation match. Alternatively, prefer `read` then `write` for non-trivial changes over `edit` with a long `oldString`.
- **Signature:** `Error: Could not find oldString in the file. It must match exactly, including whitespace, indentation, and line endings.`
- **Registry:** new; no matching registry item or earlier daily candidate found.

- **Signature:** `Review evidence rejected: evidence file changed`
- **Registry:** raises recurrence of stale-manifest variants tracked in 2026-10-22 C2 and 2026-10-20 C3.
