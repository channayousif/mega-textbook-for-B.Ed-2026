# ADR-0002: Content Platform Architecture and Hosting

> **Scope**: Document decision clusters, not individual technology choices. Group related decisions that work together (e.g., "Frontend Stack" not separate ADRs for framework, styling, deployment).

- **Status:** Accepted — **"Hosting & delivery" bullet superseded by [ADR-0008](0008-production-deployment-architecture.md)** (2026-07-21): production delivery is a pull-based, CI-gated deploy to the self-hosted origin, not Vercel/GitHub Pages. All other decisions in this cluster stand.
- **Date:** 2026-07-17
- **Feature:** 001-content-platform
- **Context:** The B.Ed textbook must be a public, bilingual, low-bandwidth reading platform that stays economically maintainable across 40+ courses and years of growth, on free/low-cost tiers, with no server security surface for the reading layer. Constitution Art. V mandates strict separation of content (a versioned, diffable, reviewable textbook) from application state (users/grades/submissions, which land in later specs), and Art. V.4 requires that "one course = one content module" — adding a course must not touch platform code. This feature also had to *replace an existing WordPress site* at a2ahs.com. The framework, content substrate, navigation/search mechanism, and hosting are tightly coupled and would change together, so they are captured as one cluster.

## Decision

Adopt a **static, Git-versioned content platform**:

- **Framework:** Docusaurus v3 (classic preset, TypeScript config — `docusaurus.config.ts`, `sidebars.ts`).
- **Content substrate:** Markdown/MDX + `_category_.json` files in the Git repo; **no database or backend in this feature** (application state is a later-spec Supabase concern, explicitly out of scope). Content and application are separate concerns (Constitution V.1).
- **Navigation:** fully autogenerated Semester → Course → Unit sidebar from the folder structure — adding a course is content-only.
- **Search:** offline, bilingual local search via `@easyops-cn/docusaurus-search-local` (index built at build time; no hosted dependency).
- **Hosting & delivery:** static output on free tiers — Vercel primary (`vercel.json`), GitHub Pages as a documented fallback (`deploy.yml`) — built and gated by GitHub Actions CI. Deployed to the a2ahs.com docroot, replacing the prior WordPress install; served by the existing nginx vhost with `trailingSlash: true` for plain-static directory URLs.

## Consequences

### Positive

- **Diffable, reviewable content** with no runtime server to secure; anything in the bundle is public by design (Constitution V.2).
- **Free-tier friendly and low-maintenance**; the whole site is ~4.4 MB of static files that any static host (or the existing nginx) serves directly.
- **Content-only growth** — a new course is new folders + metadata, picked up automatically by nav/search/validation (Constitution V.4, SC-006).
- **Portable** — replacing WordPress required only dropping the build into the docroot; no PHP/DB dependency for the reading layer.

### Negative

- **Docusaurus SSG quirks** must be respected — e.g., `"type": "module"` in package.json breaks the CommonJS server bundle (`require.resolveWeak`), and identical i18n sidebar labels collide as translation keys. Both bit us and are now documented.
- **Search is built at build time and is English-tuned** — Urdu tokenization quality is an open risk (only `en` is indexed today) that may force a custom segmenter or a hosted engine.
- **No dynamic features** in this layer; anything interactive (accounts, submissions) requires the separate backend specs.

## Alternatives Considered

- **A. Astro Starlight.** Excellent i18n/RTL and performance. *Rejected:* smaller MDX-component ecosystem and it would break the Constitution's Docusaurus lock-in; migration cost without clear benefit.
- **B. VitePress.** Fast, simple. *Rejected:* weaker i18n/RTL story for Urdu and fewer content-component affordances.
- **C. Hand-rolled Next.js.** Maximum flexibility. *Rejected:* reintroduces server/build complexity and undermines "one course = one content module" simplicity and the low-maintenance goal.
- **D. Stay on WordPress/CMS (the incumbent).** *Rejected:* DB-backed, PHP attack surface, not diffable/reviewable as Git content, harder to guarantee the < 200 KB budget and the content-integrity build gate (ADR-0004).
- **E. Algolia DocSearch for search.** Better relevance/scale. *Rejected (deferred):* hosted dependency and application process; not free-tier-guaranteed. Kept as a future option if local search proves insufficient.
