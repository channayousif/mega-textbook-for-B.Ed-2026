## Prompt

/sp.adr — Analyze planning artifacts and document architecturally significant decisions as ADRs.

## Response snapshot

Loaded plan.md/research.md/data-model.md and the one existing ADR (0001 — scaffold scope + unit-file model). Extracted architecturally significant decisions as clusters (not atomic), applied the significance test (impact / alternatives / cross-cutting) — all passed — and created three ADRs, complementary to ADR-0001 (no conflicts):

- **ADR-0002 Content Platform Architecture & Hosting** — Docusaurus v3 static (classic, TS), content-as-Markdown/MDX in Git, content/application separation (no backend), autogenerated nav, local search (@easyops-cn), free-tier hosting (Vercel/GitHub Pages) + CI, deployed over WordPress. Alternatives: Astro Starlight, VitePress, Next.js, staying on WordPress, Algolia.
- **ADR-0003 Bilingual Reader Rendering & Print Handouts** — native i18n en/ur with default-locale fallback, self-hosted Nastaliq subset + RTL, translation_status states, client-side print-stylesheet handouts (no PDF pipeline). Alternatives: runtime switch, CDN fonts, hiding untranslated pages, build-time PDF.
- **ADR-0004 Content Integrity Build Gate & Data-Driven Catalog** — gray-matter + ajv JSON-Schema + custom checks (five-file, path, EN↔UR parity, glossary-ref, weighting-sum, no-answer-keys) as the publish gate, plus catalog/courses.json + scaffold generator for content-only growth. Alternatives: editorial-only, remark-lint, Zod, hand-created folders, prose diffing.

Each ADR clusters related changes, lists ≥2 alternatives with rationale, and gives positive + negative consequences. Verified no unresolved `{{placeholders}}`.
