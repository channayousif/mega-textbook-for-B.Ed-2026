# Pedagogy checklist (author-unit)

Apply while drafting. These are how a unit reads as *deep* rather than *long*. The human
Content gate judges most of them; use this list so you don't have to be told twice.

## Cognitive load

- **Chunk.** One idea per paragraph; one concept per subsection. Introduce a term, use it,
  move on — don't stack three new terms in a sentence.
- **Worked-example effect.** For any procedure or analytical move (e.g. "classify this
  scenario against the professionalism dimensions"), show one fully worked example *before*
  asking the learner to do it. A worked example is not the same as a definition.
- **Manage extraneous load.** No decorative digressions. If a sentence doesn't move a
  checklist sub-topic forward, cut it.

## Making concepts land

- **One concrete Pakistan-grounded example per sub-topic** (Art. III.4). Real classroom
  texture: a government primary school in Sindh, a multi-grade rural class, a city GECE
  practicum — not "imagine a teacher".
- **Contrast pairs.** Abstract distinctions (profession vs occupation; industrial vs
  inquiry; professionalism vs professionalisation) land fastest as a side-by-side of two
  short concrete cases, then name the feature that differs.
- **Name the misconception.** The `## Common misconceptions` block is not filler — state the
  wrong idea a learner actually arrives with, then correct it. This is where a lot of the
  depth lives.

## Retrieval & spacing

- **Formative = retrieval practice**, not a reading comprehension check. Ask learners to
  *produce* (define in one sentence, give an example, classify, justify) rather than
  recognise.
- **Spaced-review hooks.** End `index.mdx` with a short "Key ideas" recall list; have
  `activities.mdx` re-use a concept from earlier in the unit.

## Universal Design for Learning

- **Multiple representations.** Pair prose with at least one of: a short table, a labelled
  contrast, a numbered procedure. Every non-text element gets descriptive alt text
  (Art. III.8); no meaning carried by colour alone.
- **Accessible structure.** Semantic heading hierarchy (`##` → `###`), never skipped levels.

## Explicit vocabulary

- Define every technical term on first use, in-line, in plain words. If it's genuinely
  new to the curriculum, add a `glossary.json` entry and tag it with `<Glossary term="…">`.
- Use one term per concept consistently — don't alternate synonyms within a unit.

## Dialogic / inquiry stance (matches the EFMP-302 course description)

- Activities should ask learners to analyse, compare, and justify — "collaborative inquiry",
  "case analysis", "reflective practice" are named in the guide's course description; the
  unit's activities and teacher-notes should visibly use them.
- Teacher-notes: give the teacher one good discussion prompt and one likely wrong answer to
  work with, not just "lead a discussion".
