# Admin Guide

The **Admin** link in the signed-in navbar opens `/app/admin/`. Choose the
record or queue you need from there. The console never enters another user's
session.

## Accounts and records

Use **Users and roles** to select an account before changing its role,
verified-teacher access or suspension. Use **Classes and learner records** to
inspect a selected class, its roster, or a selected student or teacher. A
selected class can be archived or reactivated with a recorded reason. The
privilege audit shows role and access changes.

## Reviewer applications and decisions

**Reviewer applications** shows each applicant's scope and qualification
evidence. Approve or reject a pending application, or directly grant a
qualified person access to the B.Ed track, one B.Ed course, or the teaching-
licence track. Revoke a grant from the active grants list. The licence track
has no course codes. An old `reviewer` checkbox is no longer the access rule.

**Review decisions** shows the reviewer's criterion results and comments.
Record an approval, improvement request or rejection with a note. A G3/G5
approval in this queue does not mark a unit reviewed: the existing Git
certification and gates decide formal status.

## Improvements and agent jobs

Moderate reader feedback and teacher suggestions in their own queues. An
accepted teacher suggestion or an improvement decision can become one agent
job. In **Agent jobs and settings**, choose a configuration reported by the
host, select the source record and write the instructions. The heartbeat
claims approved jobs and reports its diff, checks, errors and draft PR link.
Failed jobs can be retried; **Manual export** downloads the job description
when the host is unavailable. Agent jobs never publish changes on their own.

The host contract and deployment order are in
`specs/025-admin-review-workflows/quickstart.md` in the repository.
